# 绘本方法论详解（实测提炼）

来源：亲子沙龙第六期筹备期间在自部署 Qwen-Image-2.1 上的全链路实测（双角色 12 页零漂移、中文零错字、组合拳 17 张 118s）。每条结论都带"为什么"——理解了才能在新故事上举一反三。

## 一、四步流程的设计逻辑

### 1. 分镜（写故事）
8–12 页是童书最佳节奏。分镜时**同时决定画面**：每页一句话 caption + 一个可视化场景。标出 2–3 个"大场面页"（远景全景/大俯瞰/大仰视）——这类页构图复杂，后面要挂构图参考。

### 2. 定妆照（anchor）—— 全书质量的根
- 用 **quality 档**（不要 fast）：这张图的形象会通过 edits 传递到每一页，锚点糊全书糊，值得多花十几秒。
- 所有角色**同框全身**、动作中性、浅色干净背景、无场景元素——给后续编辑留最大自由度。
- **风格串在这一步定死**。画风（平面/厚涂/3D）来自 prompt 里的风格串，不是模型自动延续；锚点图带上最终风格，全书才统一。
- 为什么不链式传递（每页从上一页 edit）：edits 是"有偏编辑"，误差逐页累积，4–5 页后角色五官/配色明显漂移。全部从同一张 anchor 出发，每页误差独立，不累积。

### 3. 逐页生成（fast edits）
- **为什么用 edits 而不是文生图**：文字描述无法穷尽角色细节（毛色渐变、配饰位置），图到图才锁得住形象。
- **四要素**（景别/机位/姿态/位置）每页写全：单图 edits 会连**构图**一起继承 anchor——两张图放一起，模型默认保持相似构图。不显式指定四要素，整本书每页构图雷同（双人对站特写复读机，实测坑）。
- **大场面页挂构图参考（image2）**：先 fast 文生图一张"简笔构图示意"（~6s），作为第二张参考图。prompt 声明 Picture 1 管形象、Picture 2 管构图，各司其职。构图示意必须是**淡彩剪影**风格——画得太真实会和 Picture 1 抢"画风话语权"。
- 实测效果：多参考页角色零漂移 + 构图完全跟随参考。

### 4. 组装
`build_book.py`：封面 + 内页 + caption → 单文件 HTML（StPageFlip 拟真翻页，base64 内嵌，离线可开，`#页码` 深链）。厚涂风格 PNG 大（14 页可 30MB+），在意加载可先压 JPEG（`build_book` 的 `img_to_dataurl` 会按扩展名写 mime，换 .jpg 文件即可）。

## 二、prompt 拼接公式

```
anchor = 角色全描述 + 站位 + "干净的浅色背景" + 风格串          (quality t2i)
cover  = 封面场景 + 「书名」文字指令 + 风格串                    (fast t2i)
comp   = "简笔构图示意：" + 构图描述 + "淡彩剪影"               (fast t2i, 不拼风格串)

普通页 = KEEP + "。新场景：" + 四要素场景 + "，" + 风格串         (fast edits, image=anchor)
大场面页 = "Picture 1 是角色定妆照，Picture 2 是构图参考。以 Picture 1 为准保持角色
           形象与画风完全不变，严格按 Picture 2 的构图与景别安排画面布局。
           新场景：" + 四要素场景 + "，" + 风格串                (fast edits, image=anchor, image2=comp)
```

### KEEP 锁定串写法
`保持 + 角色名 +（外貌特征清单：主色/服饰/标志物/体型）+ 的形象、配色与画风完全不变`
特征清单要**可视化、带颜色**（"青色交领汉服、背木质书箱、束发飘带"），不要写性格类抽象词。双角色各写一段，用括号分组。

### 风格串选型表（实测）
| 风格串 | 效果 | 适用 |
|---|---|---|
| `儿童绘本插画，明亮色彩，柔和笔触，简洁构图` 类 | 平面插画风，PNG 小（14 页 ~14MB） | 默认；低成本、画风稳 |
| `国风厚涂儿童绘本插画，青绿山水意境，体积光与柔和景深，立体厚涂质感` | 立体厚涂，细节多、PNG 大 | 想要"电影感"画面 |
| `皮克斯3D动画风格` | 3D 渲染感 | 实测有效（M3 样张） |

**关键**：立体感靠风格串**整体切换**，且必须在 anchor 阶段就用最终风格串。往平面风格串里追加"体积光/景深"等词**无效**——模型对"整体风格描述"敏感，对"追加修饰词"不敏感（实测）。

## 三、中文文字规则

- 短文字（书名/招牌/路牌/横幅）直接写进 prompt，用「」括出：`画面顶部手写体中文大标题「云梦仙踪」`、`碑上刻着「云梦泽」三个字`。quality 与 fast（Viggle 6-step）档都可靠。
- 指定**位置 + 字号层级**（"顶部大标题 / 标题下一行小字"）比只给文字效果好。
- 长文案海报排版未充分验证；指南层面控制在一行内。
- 复核方法：生成图后对文字区域放大裁切转写核对（原项目用 `crop_zoom.py`，skill 未收录，用 headless Chrome 截图放大亦可达）。

## 四、性能实测（1024×1360）

| 档位 | 引擎耗时/张 | 说明 |
|---|---|---|
| quality 20 步 | ~12s | anchor 用；封面可用 |
| fast（Viggle v0.3 6-step）| 文生 3.2–5s / 编辑 4–6s | 内页用；文字/场景遵循全达标 |
| fast（DMD2 2-step）| ~1.6s | 备选；小字笔画劣化、场景遵循略偏 |

全场 15 组家庭（封面+定妆照 quality、内页 fast）GPU 总时长 ~22 分钟。服务端串行排队，客户端 timeout 给 300s。

## 五、踩坑清单

1. **链式 edit 漂移**：永远从 anchor 出发（见上）。
2. **构图复读**：每页写全四要素（见上）。
3. **本机代理劫持内网请求**：系统代理（Clash 等）会把发往内网服务地址的请求劫持出 502。`gen_book.py` 已自动清代理环境变量并设 `NO_PROXY=*`；手写 curl/脚本时注意。
4. **并发 500**：底层引擎非线程安全，服务端 v2 起有全局串行锁。并发调用会排队而非报错，但 timeout 要给足；`GET /queue` 可看实时排队。
5. **光影词打补丁无效**：换风格串重做 anchor（见上）。
6. **构图参考太真实抢画风**：comp 用"淡彩剪影"措辞。
7. **PNG 体积**：厚涂 14 页 33.8MB；现场分发在意加载速度 → 压 JPEG 再组装。
8. **文字复核别省**：中文渲染虽可靠，封面书名/招牌仍要放大目检一遍，错字毁全书。
