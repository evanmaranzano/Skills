## §1 解说稿方法论（步骤②）

### 1.1 动笔前规划（写进 script.md 顶部元信息，六行）

```text
主题：这条视频具体讲什么
受众：最需要它的是谁（处境/卡点/已知水平/常见误区，写行为画像不写年龄收入）
核心问题：观众卡在哪里
核心价值：看完能获得什么判断或行动
主目标：唯一要推动的结果（涨粉/收藏/转发/评论…只选一个，CTA 与它一致）
主线一句话：这条视频只想让谁明白什么（若只能说"讲 A、B、C"，继续砍）
```

### 1.2 一稿一刀口

- 一条片只服务**一个核心认知翻转**。论点是素材池不是清单，支撑不了主线的内容舍弃。
- 主线依次检查：是否反常识 → 是否与观众近期场景直接相关 → 是否提供非替代性的理解。
- 建论点树再动笔：主张 / 证据 / 案例 / 反例 / 信息缺口。缺口处理：补可核实来源、降级为"个人经验/假设场景"、或删精确断言（与 SKILL.md §2① 的 research.json 对接）。

### 1.3 内容类型 × 信息骨架（选一套，说明一句理由）

| 内容类型（回答"是什么"） | 信息骨架（回答"按什么顺序"） |
|---|---|
| Story / Teaching / Opinion / Problem Solution / Myth Breaking（辟谣）/ Comparison | AIDA / PAS / BAB / 倒金字塔 / Story Spine |

科普/辟谣选题默认 `Myth Breaking + PAS`；机制讲解默认 `Teaching + 倒金字塔`。

### 1.4 节奏硬规则

- **每 8–12 秒**引入一个新观点/数字/反转/画面变化；前 30 秒至少兑现一个具体价值点。
- 每约 30 秒一次可感知推进（金句/数据冲击/判断标准）；每约 60 秒一句**可截图、可复述**的判断句（必须承载事实或方法，不是口号）。
- 先写带时间的节奏节点再写正文；节点总时长 = 目标时长。
- 情绪曲线由事实与认知推进产生（好奇→意外→认同→获得感→行动），不靠感叹号。
- 语速仍按 SKILL.md 实测口径（edge-tts 4.2–4.7 字/秒）。JVF 的"220–260 字/分钟"是人类口播估值，不采用。

### 1.5 句子工程与口语取舍

- 一句一个主要意思，目标 20 字、超 25 字必拆（与现有字幕 ≤20 字红线一致）。
- 数据的来源/样本/结论拆开说，不把相关性写成因果。
- 术语首次出现用"英文原词（中文说明）"，如 prefix cache（前缀缓存）；先给场景或机制，再给名称。
- 保留有信息量的口语（短句停顿、自问自答、对"你"说话）；删除填充词、模糊限定、"首先/其次/综上所述"公文腔、连续"然后/后来"。
- 开场禁"大家好，我是……今天聊……"。

### 1.6 基调红线

- 不用焦虑/灾难/淘汰叙事推动观看："慌了/崩塌/毁灭"→ 改为可核实的结构变化、具体代价、约束。
- 结尾不空洞升华（"令人深思/太震撼了"），交付可操作判断、方法或边界。
- 没有真实场景时明确标注"假设场景"；悬念可以有，主题不能藏。

### 1.7 技术选题附加规则

- 先现象/真实问题，再底层机制；机制展开成可检查的因果链，不跳步。
- 每个核心判断后回答"这对实际工程意味着什么"（判断标准/设计约束/验证方式）。
- 对比用一致维度（工作单元/成本/可靠性/适用条件）；类比只解释一个关系并说明边界。
- 短视频只保留支撑主结论的最短因果链，不逢概念就讲三层。

### 1.8 稿件自检（1–5 分，任一项 <4 改一轮；每项附一条证据或待改问题）

`Hook / 节奏 / 情绪 / 可听性 / 价值 / 评论潜力 / 转发潜力 / 事实安全`

## §2 开场钩子方法论（步骤③ beat 1 专项设计）

### 2.1 四类失效诊断（自检顺序，后者不能掩盖前者）

| 失效 | 症状 | 修复 |
|---|---|---|
| 延迟 Delay | 主题第二句后才出现，开头是"太疯狂了"式泛悬念 | 主题/对象/结果提到第一句；只听第一句就能判断是不是自己要看的 |
| 困惑 Confusion | 句子长、概念堆叠、有多种理解 | 少而常用的词；一句一个动作；主动句；脱离上下文单读只有一种理解 |
| 无关 Irrelevance | 讲清楚了但观众不觉得与自己有关 | 用"你/你的"表达痛点；个人经历翻译成观众处境 |
| 无兴趣 Disinterest | 清楚且相关但没有想看下去的问题 | A/B 对比：观众已知做法 A vs 视频给出的 B；B 必须在片内兑现 |

### 2.2 三件套

- **Context Lean**：前 1–2 秒同时完成「讲清主题」+「让目标观众产生关联」。入口可用：痛点/收益/误区/对比/场景/结果。
- **Scroll Stop Interjection**：一句转折打断滑动惯性——"但问题是 / 其实很多人搞反了 / 你以为是 X，其实是 Y / 表面看是 A，起作用的是 B"。
- **Contrarian Snapback**：`如果你想要 X，不要只盯着 Y，真正决定结果的是 Z`。Z 必须真实、有价值、服务主体；不承诺片内无法兑现的结果。

### 2.3 视觉钩子公式（beat 1 落地）

```text
屏幕短字(3–8 个汉字，≤12) + 明确主体 + 一点运动 + 与口播同向的信息
```

- 落地方式：H3 开场 beat 的 prompt 直接把"明确主体+运动"写进去；矢量叠加层放屏幕短字（`Reveal` 大字组件，字重 900）。
- 第一帧画面必须独立表达痛点/冲突/反常识；禁止纯静态开场、禁止堆满文字。

### 2.4 前 30 秒结构

```text
0–2 秒：主题 + 目标观众 + 相关性
2–6 秒：反差/打断
6–15 秒：新观点
15–30 秒：第一个具体价值点（判断标准/对比框架/误区纠正/马上能用的方法/降门槛比喻）
```

### 2.5 产出要求

写 script.md 时为 beat 1 出 3 个方向不同的开头（A 痛点型 / B 反常识型 / C 场景型），按 `吸引力/主题清晰度/相关性/停留潜力` 定性评分选一个，把选中版的「屏幕大字 + H3 prompt 要点」写进 beats.json 的 beat 1。常用的三句模板：痛点型/反常识型/对比型见来源仓库 video-hook-builder。

## §3 分镜演出方法论（步骤③，约束 vector_* 镜头）

### 3.1 一镜一结论，切镜是例外

- 一个 vector 镜头 = 观众能带走的**唯一结论**，不是一张 PPT 页。镜头内完成：
  `命题 → 对象/证据 → 关系展开 → 判断 → HOLD`。
- **切镜必须同时满足**：①新内容留下不同于上一镜的结论；②现有空间拓扑无法用展开/聚焦/变色/替换表达。禁止以"旁白换句了""多点变化"为切镜理由。
- 相邻镜头合并审查：逐个检查 Scene N→N+1 边界，能延续就合并；**相同主体结构连续 ≤2 镜，第 3 镜必须换语法或换拓扑**。
- 镜头时长参考：单一判断 4–7s、普通解释 8–12s、复杂流程/对比 12–18s（60–180s 的片即 8–15 个 vector beat 量级）。

### 3.2 旁白可见拍与音画对齐

- 旁白先说关系，画面短暂延迟出现（观众先听到再看到）；一个完整句子最多一个主要画面动作；动作落在关键动词（变成/连接/排除/对比/锁定）。
- 每引入 2–4 个元素留一次呼吸拍；密度来自层次不来自持续运动。
- 屏显、字幕高亮、旁白三者说同一命题：同一对象同名、同语义色；不得出现"字幕说风险、画面是绿色"。
- 不得提前泄露后段概念；真要预告必须显式标"预告"。
- beats.json 增强字段（可选，向后兼容）：`conclusion`（本镜唯一结论）、`shot_grammar`（§3.3 语法）、`motion`（§3.5 动词）、`hold_f`（落定后 HOLD 帧数 ≥30）。字段写全，⑥ 步实现和 ⑧ 步验收都有据可查。

### 3.3 七种镜头语法 × 空间拓扑（方向即语义，不得为好看翻转）

| 语法 | 叙述任务 | 空间拓扑 | 终态 |
|---|---|---|---|
| 结论 | 先回答"所以呢" | 标题上/左，结论落下方 | 可复述结论 |
| 分类 | 给观众地图 | 同层类别按阅读方向排列 | 当前类别被标记 |
| 流程 | 解释如何发生 | 起点左→结果右，箭头按因果接通 | 完整路径 |
| 层级 | 解释沉淀或依赖 | 基础下→过渡中→结论上 | 顶层被确认 |
| 问题-方案 | 建立价值 | 问题左 ↔ 方案右 | 方案成立(Green) |
| 对比 | 支持选择 | A 左 ↔ B 右，中间关系符号 | 推荐态清晰 |
| 行动/CTA | 变成下一步 | 步骤按顺序排列 | 最小行动被保留 |

### 3.4 单场景六段节奏（一个 vector beat 内部的时间配比）

| 阶段 | 比例 | 旁白任务 | 画面任务 |
|---|---|---|---|
| 预备 | 0–5% | 承接上一句 | 保留锚点，主体未出现 |
| 命题 | 5–20% | 抛出结论/问题 | 主标题先到 |
| 锚定 | 20–35% | 说出第一个对象 | 主对象/起点出现 |
| 建构 | 35–65% | 逐句说明关系 | 每个关系补一个对象/线/条件 |
| 判断 | 65–80% | 给出风险/推荐/选择 | 中性转语义色 |
| 停留 | 80–100% | 消化收句 | 最终关系保持（HOLD ≥1s）再转场 |

实现提示：场景组件按 `beat.dur` 乘以上述比例算各元素入场帧，替代拍脑袋写 interpolate 断点。

### 3.5 动效语义词典（映射到模板组件）

| 动词 | 语义 | 用模板什么实现 | 必须留下的终态 |
|---|---|---|---|
| SLAM | 命题落位 | spring 放大 + blur→0（StatCard 入场式） | 主命题可读 |
| CASCADE | 同级对象按序建立 | Reveal 按 i*8 帧错峰 | 全部仍可读 |
| LOCK | 焦点锁定 | 3px 状态边线 / 单次描边 | 焦点明确 |
| CONNECT | 因果接通 | 描画线 interpolate 宽度 0→全长 | 路径完整 |
| CHECK | 通过确认 | 单次 Green 状态出现 | 验收态可读 |
| FLAG | 风险指认 | Coral 状态即时出现 | 风险可辨认 |
| DIM | 非焦点后退 | opacity 分级（§4.6） | 不与焦点竞争 |
| RESOLVE | 解法成立 | 中性→Green 变色 | 推荐路径成立 |
| HOLD | 结论保留 | 无动画保持 ≥1s | 不新增信息 |
| FADE OUT | 片尾退出 | SceneShell fade | 只用于最终镜 |

- 一个强调动作只改一个维度（颜色/描边/局部缩放/位置，四选一）。
- 同镜头标题、主对象、辅助关系不得同方向同速度进场。
- 术语写进 beats 时必须带对象+终态，如"品牌模板 RESOLVE 为 Green 并 HOLD"。

### 3.6 信息密度红线（无空帧）

- 每个镜头必须有明确信息载荷（文案/数据/视觉冲击/节奏点），禁空帧。
- 镜头 ≥4s 必须说得出这 4 秒在表达什么，否则砍；≤1s 必须有强视觉刺激，否则废。
- "安静一下"要承载内容：静默是信息不是空白（如 H3 呼吸镜配金句字幕）。

## §4 视觉主题：Graphite Rule Console（步骤⑥可选默认主题）

> 适合犀利科普/机制讲解。启用方式：index.tsx 顶部把配色/字号常量换成下表（或定义
> `THEME='graphite'` 分支），**关闭 EmberField 粒子层**（该规范禁环境粒子与光晕），
> 背景恒 #181916。现有模板配色（深空+金）适合叙事/情绪类选题，两者按选题二选一。

### 4.1 Token

| Token | 值 | 语义 |
|---|---|---|
| Canvas | `#181916` | 暖近黑背景（禁纯黑，抵消导出提亮）；全片唯一背景 |
| Panel | `#282824` | 信息面板 |
| Ink | `#F4F1EA` | 主标题/关键暖白文字 |
| Muted | `#C0BBB1` | 说明/未激活 |
| Hairline | `#4C4942` | 静态边线 |
| Amber | `#F0A93B` | 章节锚点/当前焦点（系统 chrome，不计入内容焦点） |
| Coral | `#FF6A61` | 风险/错误/反例 |
| Green | `#61D394` | 推荐路径/完成 |
| Blue / Violet | `#72A9FF` / `#A98CFF` | 内容属性/第二三阵营，**不表示状态** |

语义色纪律：同一对象状态变化只用一种主语义色；Coral/Green 是状态，Blue/Violet 是属性；已有 Coral 或 Green 阵营时其他容器不描彩边。

### 4.2 字号层级（30fps 1080p）

主标题 900/76px → 大数字 850/48px → 节点次标题 850/38px → 说明 700/34px → 章节锚点(等宽) 700/22px → 标签 700/18px → 字幕 650/30px。负字距禁用；文案过长先缩写不改字号。

### 4.3 留白与字幕

内容左右边距 96px、顶部 50px；**内容底部预留 154px** 不得进主体（我们的字幕区红线 260px 更保守，继续用 260px，此处 154px 是下限）；章节锚点 = 左上琥珀竖线 4×28px + `N/M 章节名`；命题前琥珀标题竖线 8px；面板 4px 圆角、3px 状态左边线、禁大圆角卡/玻璃拟态/层层套卡。

### 4.4 动效时长基准

章节锚点 0.30s 轻推 / 主标题 0.46s 快速落位 / 节点 0.30–0.40s / 流程线 0.56s 描画 / 状态词 0.24–0.32s / 结论胶囊 0.30s 轻回弹。动效只发生在旁白关系词或句末重音处；背景无环境动效。

### 4.5 DIM 三档（压制非焦点不等于消失）

| 等级 | 下限 | 适用 |
|---|---|---|
| 轻 | opacity≥0.70 | 对比对象仍需逐字阅读 |
| 中 | opacity≥0.55 | 仍有解释价值但非焦点 |
| 强 | opacity 0.40–0.55 | 仅无需阅读的冗余元素；承载风险/条件/结论的对象禁用 |

### 4.6 禁止项（Graphite 模式下追加）

纯黑/纯白背景、满屏网格、幽灵文字、局部光晕、霓虹、粒子、毛玻璃、全屏线性渐变、假网页/假评论区/无来源图表、每句话同方向飞入、逐字打字机。

## §5 语义音效层（2026-09-13 已实装）

来源仓库方法：音效是第三信息通道，一声 = 一次可解释的状态迁移（定位/因果/确认/风险/收束），**不为每个动画制造存在感**。要点：

- 事件集：`card.enter / flow.connect / card.lock / check.confirm / risk.flag / conclusion.slam / scene.transition`；口播定位点→事件映射表见来源 `Skill/creator-playbook/skills/knowledge-video-sfx/references/event-taxonomy.md`。
- 密度档位：sparse 2.0–3.5 / balanced 3.5–5.0 / dense 4.5–6.0 条/分钟（复查线不是配额）；相邻 cue ≥3s；同一事件全片固定同一素材（身份声）；`conclusion.slam` 全片 ≤3 处。
- 合法两声配对：破-立（risk.flag→check.confirm）、坑-规则（risk.flag→card.lock）、闸门-通过（card.lock→check.confirm，间隔 ≥3s）。
- 产物：项目级 `sfx-cues.yaml`（event/visual_anchor/narration_anchor/timing/candidates/gain/status），时间码从 clips/timing.json 回填。
- **实装（skill 内）**：`assets/sfx/sfx-catalog.yaml` + 14 条素材（Mixkit Sound Effects Free License，7 事件×主/备）；`scripts/make_sfx.py` 一条命令产出 cues+复制素材+打印 SFX 数组；`qa_check.py --sfx-cues` 校验密度/slam/间隔/文件。

## §6 发布物料（可选扩展）

成片交付后可按 gbro-cover-design 方法补发布物料：3 个候选标题（数字+反常识 / 身份+痛点 / 悬念+利益，前 30 字仍清楚）+ 3:4 竖版封面提示词（10 种构图风格，人物表情/背景/字体/颜色四维选项；本机可用 image2-gen 实际出图）。中文标题文字生成后必须逐字核对（图片模型常写错中文字）。
